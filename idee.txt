```python
import requests
import json
import os

# --- KONFIGURATION ---
OPENROUTER_KEY = "DEIN_OPENROUTER_KEY_HIER"
# Pfade (Standardpfade für 2026)
CONTINUE_CONFIG_PATH = os.path.expanduser("~/.continue/config.json")
OPENCODE_CONFIG_PATH = os.path.expanduser("~/.config/opencode/opencode.json")

def fetch_free_models():
    print("📡 Scanne OpenRouter nach kostenlosen Modellen...")
    headers = {"Authorization": f"Bearer {OPENROUTER_KEY}"}
    response = requests.get("https://openrouter.ai/api/v1/models", headers=headers)
    
    if response.status_code != 200:
        return []

    # Filter für :free Modelle und Sortierung nach Kontext/Relevanz
    free_models = [m for m in response.json()['data'] if m['id'].endswith(':free')]
    return free_models

def generate_configs():
    models = fetch_free_models()
    if not models:
        print("❌ Keine kostenlosen Modelle gefunden.")
        return

    # Top-Empfehlungen für Web-Dev (basierend auf Benchmarks 2026)
    # Wir suchen bevorzugt nach 'coder', 'gemini' oder 'llama'
    best_coder = next((m for m in models if "coder" in m['id']), models[0])
    best_fast = next((m for m in models if "flash" in m['id']), models[0])

    # 1. CONTINUE.DEV CONFIG (JSON)
    continue_data = {
        "models": [
            {
                "title": f"FREE: {best_coder['id'].split('/')[-1]}",
                "provider": "openrouter",
                "model": best_coder['id'],
                "apiKey": OPENROUTER_KEY
            },
            {
                "title": "DeepSeek V3 (Paid/Cheap)",
                "provider": "openrouter",
                "model": "deepseek/deepseek-chat",
                "apiKey": OPENROUTER_KEY
            }
        ],
        "tabAutocompleteModel": {
            "title": "Autocomplete Free",
            "provider": "openrouter",
            "model": best_fast['id'],
            "apiKey": OPENROUTER_KEY
        }
    }

    # 2. OPENCODE CONFIG (JSON)
    opencode_data = {
        "model": f"openrouter/{best_coder['id']}",
        "small_model": f"openrouter/{best_fast['id']}",
        "api_keys": {"openrouter": OPENROUTER_KEY},
        "theme": "opencode"
    }

    # Dateien schreiben
    with open(CONTINUE_CONFIG_PATH, "w") as f:
        json.dump(continue_data, f, indent=2)
    
    # Ordner für OpenCode erstellen falls nötig
    os.makedirs(os.path.dirname(OPENCODE_CONFIG_PATH), exist_ok=True)
    with open(OPENCODE_CONFIG_PATH, "w") as f:
        json.dump(opencode_data, f, indent=2)

    print(f"✅ Konfigurationen aktualisiert!")
    print(f"👉 Primäres Modell: {best_coder['id']}")
    print(f"👉 Autocomplete:   {best_fast['id']}")

if __name__ == "__main__":
    generate_configs()
```

### Wie geht es weiter?

Soll ich dir zeigen, wie du dieses HTML-File als **PWA manifest** deklarierst? Dann kannst du es unter Android/iOS „Installieren“ und hast es wie eine native App auf dem Homescreen.

Das Problem liegt meist an einem klassischen JavaScript-Konflikt: Wenn man ein Element (die Karte) anklickt, das selbst ein klickbares Element (die Checkbox) enthält, „verschlucken“ sich die Ereignisse gegenseitig (**Event Bubbling**). Außerdem müssen bei dynamisch erstellten Karten die Funktionen sauber im globalen Bereich (`window`) liegen.

* **Einschränkungen:** Wo macht das Modell Fehler?

Für eine **intelligente Bundle-Maschine**, die autonom arbeitet, reicht ein reines Frontend (HTML/JS) nicht mehr aus. Du benötigst eine **Server-Logik** (Backend), die wie ein "Wachhund" fungiert.

Hier ist das Konzept für den **Butler Engine v1**:

### 1. Die Architektur der "Maschine"

Um jeden Tag zu prüfen und dich zu informieren, nutzen wir ein **Backend-Script** (z. B. Node.js oder Python), das per **Cron-Job** (Zeitgesteuerter Task) einmal täglich läuft.

### 2. Der Arbeitsablauf (Workflow)

1. **Check:** Die Maschine ruft die OpenRouter API auf.
2. **Validierung:** Sie prüft, ob die IDs deiner gespeicherten Bundles (z. B. "Frontend-Bundle") noch in der Liste der `:free` Modelle existieren.
3. **Heilung:** Ist ein Modell verschwunden, sucht die Maschine nach dem nächstbesten Ersatz (z. B. "Llama-3-8B" weg -> Suche nach "Llama-3.1-8B").
4. **Notification:** Die Maschine schickt dir eine Zusammenfassung (via **Telegram**, **Discord** oder **E-Mail**).

### 3. Das Logik-Script (Beispiel Node.js)

Dieses Script simuliert die tägliche Prüfung:

```javascript
const axios = require('axios');

// Deine vordefinierten Bundles
let bundles = {
  "coding_pro": ["google/gemini-2.0-flash-lite:free", "qwen/qwen-2.5-coder-32b:free"],
  "creative": ["meta-llama/llama-3.1-8b-instruct:free"]
};

async function checkAndInform() {
  const { data } = await axios.get('https://openrouter.ai/api/v1/models');
  const liveFreeIds = data.data.filter(m => m.id.endsWith(':free')).map(m => m.id);
  
  let report = "🤖 BUTLER DAILY REPORT\n------------------\n";
  let updatesMade = false;

  for (let [name, ids] of Object.entries(bundles)) {
    let available = ids.filter(id => liveFreeIds.includes(id));
    if (available.length < ids.length) {
      report += `⚠️ Bundle '${name}' unvollständig! (${available.length}/${ids.length})\n`;
      // Hier Logik für "Neue erstellen" (Suche nach Keywords)
      updatesMade = true;
    } else {
      report += `✅ Bundle '${name}' ist stabil.\n`;
    }
  }

  // Sende dir die Info (z.B. via Telegram Bot API)
```

Hier ist die Logik für die **Bundle-Machine (v21-Logic)**. Um eine „intelligente“ Maschine zu haben, die autonom Kategorien wie **Logic, Code oder Vision** füllt, nutzen wir ein Scoring-System.

Dieses Python-Skript dient als dein Backend-Agent (z. B. für GitHub Actions). Es analysiert die Modelle, bewertet sie nach deinen Tags und erstellt automatisch die passenden Bundles.

### Die Bundle-Machine (Python Backend-Logic)

```python
import requests
import json
from datetime import datetime

# KONFIGURATION
API_URL = "https://openrouter.ai/api/v1/models"
GITHUB_WEBHOOK = "DEIN_WEBHOOK_URL" # Optional für Benachrichtigungen

def fetch_free_models():
    try:
        response = requests.get(API_URL)
        response.raise_for_status()
        # Nur :free Modelle filtern
        return [m for m in response.json()['data'] if m['id'].endswith(':free')]
    except Exception as e:
        print(f"Fehler beim API-Abruf: {e}")
        return []

def score_model(model, category_keywords):
    """Bewertet ein Modell basierend auf Keywords in Name/Beschreibung."""
    text = (model['name'] + model['id'] + (model.get('description') or "")).lower()
    score = 0
    for keyword in category_keywords:
        if keyword in text:
            score += 1
    # Bonus für große Context-Fenster
    score += (model.get('context_length', 0) / 100000) 
    return score

def build_bundles(models):
    categories = {
        "Coding_Pro": ["code", "coder", "python", "javascript", "programming"],
        "Logic_Reasoning": ["math", "logic", "reasoning", "thought", "science"],
        "Creative_Unfiltered": ["uncensored", "nosys", "unfiltered", "story", "rp"],
        "Vision_Multimodal": ["vision", "image", "multimodal", "clip"]
    }
    
    final_bundles = {}
    
    for cat_name, keywords in categories.items():
        # Sortiere alle Modelle nach Score für diese Kategorie
        scored_list = sorted(
            models, 
            key=lambda m: score_model(m, keywords), 
            reverse=True
        )
        # Nimm die Top 3 Modelle für das Bundle
        final_bundles[cat_name] = [
            {"title": m['name'], "model": m['id'], "provider": "openrouter"} 
            for m in scored_list[:3]
        ]
        
    return final_bundles

def main():
    print(f"--- Butler Engine Start: {datetime.now()} ---")
    free_models = fetch_free_models()
    
    if not free_models:
        return

    bundles = build_bundles(free_models)
    
    # Speichere die Bundles als JSON für das Frontend
    with open('current_bundles.json', 'w') as f:
        json.dump(bundles, f, indent=2)
        
    print("Bundles erfolgreich aktualisiert.")
    for name, items in bundles.items():
        print(f"✅ {name}: {len(items)} Modelle integriert.")

if __name__ == "__main__":
    main()

```

Soll ich als Nächstes die **GitHub Action** für deine Bundle-Machine vorbereiten?

Ja, es gibt signifikante Unterschiede. Diese basieren primär auf zwei Faktoren: den **Trainingsdaten** und dem **Tokenizer**.

### 1. Trainingsdaten (Das Wissen)

LLMs lernen Sprache durch Statistik.

* **Englisch-Dominanz:** Da das Internet primär englischsprachig ist, machen englische Texte oft über **90%** der Trainingsdaten aus.
* **Qualität:** Ein Modell versteht deutsche Nuancen oder Dialekte schlechter, wenn es nur wenig deutsche Literatur oder Web-Inhalte gesehen hat. Es beginnt dann zu "anglizieren" (deutsche Sätze mit englischer Grammatik).

### 2. Der Tokenizer (Die Effizienz)

Bevor eine KI liest, zerlegt sie Text in kleine Stücke (Tokens).

* **Effizienz:** Englische Wörter sind oft ein Token (z. B. `Apple`).
* **Fragmentierung:** Bei selteneren Sprachen (oder komplexem Deutsch) muss die KI Wörter in viele kleine Schnipsel zerlegen (z. B. `Donaudampf` -> `Donau` | `dampf`).
* **Folge:** Je mehr Tokens für ein Wort benötigt werden, desto weniger Kontext passt in den Speicher und desto langsamer/fehleranfälliger wird die KI in dieser Sprache.

### 3. Benchmarks & Spezialisierung

* **Global Players:** Modelle wie **GPT-4o** oder **Llama 3** sind "multilingual", d.h. sie beherrschen ca. 20–50 Sprachen sehr gut.
* **Spezialisten:** Es gibt Modelle wie **Mistral** (stark in Französisch/Deutsch) oder **Qwen** (stark in Chinesisch), die in ihren jeweiligen Sprachräumen oft besser abschneiden als US-Modelle.

### 1. Spezialisierung der Architektur

* **General Purpose (z. B. Llama-3):** Beherrscht viele Sprachen "gut", ist aber oft auf allgemeine Text-Logik optimiert.
* **Code-Spezialisten (z. B. Qwen-Coder, DeepSeek-Coder):** Diese Modelle wurden auf Milliarden Zeilen Code nach-trainiert. Sie verstehen die **Syntax-Struktur** und **Bibliotheken** tiefer als Generalisten.
